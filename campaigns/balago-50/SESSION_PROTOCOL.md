# Протокол контекста ChatGPT ↔ Claude Code

## Почему это нужно
Длинные чаты могут терять детали при сокращении/переполнении контекстного окна. Поэтому неизменяемые правила и принятые решения лежат в Git, а новый чат каждый раз загружает небольшой актуальный набор. Автоматическая «память» модели или пересказ чата **не заменяют коммиты и проверку файлов**.

## Контекст в ChatGPT (режиссёр + сценарист)
- В одном чате можно обсуждать концепцию/сценарий/рецензию одного видео. Для другого ролика предпочтителен **новый чат**.
- Принятые решения записывать в сценарий или журнал; не полагаться на то, что модель «помнит всё».
- Для продолжения в новом чате достаточно: репозиторий `adiletzainidinov/balago-video`, номер `BG-NNN`, ссылка на PR, задача и файл checkpoint. Не нужно копировать всю историю переписки.
- Если модель путает версии, попросить перечитать соответствующие файлы и сравнить Git SHA.

## Контекст в Claude Code (исполнитель)
- Одна **свежая сессия** на каждый ролик, отдельная ветка/PR. Не загружать сценарии всех 50 видео в каждую сессию: читать только свой сценарий, бренд-факты, правила, производственное задание, актуальный checkpoint.
- Команда `/context` в поддерживаемых версиях Claude Code показывает использование контекста; `/compact` сжимает текущую длинную беседу, `/clear` очищает беседу для новой задачи. Проверять актуальные возможности своей версии через `/help`.
- **Перед /compact, /clear, новым чатом или окончанием длинной сессии:** сохранить состояние в `campaigns/balago-50/handoffs/BG-NNN.md` по шаблону `HANDOFF_TEMPLATE.md`, зафиксировать нужные изменения в Git (или честно перечислить незафиксированные файлы), дать ссылку на branch/commit/PR.
- После нового контекста заново прочитать `AGENTS.md`, `CLAUDE.md`, `README.md`, checkpoint, сценарий и `git status`/последние коммиты; не начинать с нуля, если на диске уже есть рабочий результат.
- Не хранить приватные токены, ключи и персональные данные в checkpoint. Никаких фраз «видео готово» без реального подтверждённого MP4.

## Когда менять контекст
Если собеседник повторяет ошибки, забывает ограничения, перепутал BG-001 и BG-032, контекст заполнен, или задача логически закончена — зафиксировать checkpoint и перейти к свежему чату/сессии. Конкретной универсальной границы в токенах нет.

## Критерий успешной передачи
Новый исполнитель без старого чата способен за несколько файлов ответить на вопросы: **какой ролик, какой сценарий утверждён, что уже сделано, какие ошибки остались, какой следующий шаг, где проверить результат**.
