# Проверка звука готового ролика (`audio:review`)

Инструмент слушает **настоящий звук** готового MP4/WAV/MP3 аудиомоделью
OpenAI `gpt-audio-1.5` и сохраняет отчёт о голосе, монтаже звука и эффектах.
Он ничего не меняет в роликах, не генерирует озвучку и не вызывается в CI:
платный запрос делается только при явном запуске без `--dry-run`.

- Движок: `scripts/lib/audio-review.mjs` (`runReview(opts, { transport })`).
- Локальное сравнение со сценарием: `scripts/lib/audio-review-compare.mjs`.
- CLI: `scripts/audio-review.mjs`, команда `npm run audio:review`.
- Контекст ролика №12 с проверенным размещением голосов:
  `scripts/audio-review-two-schedules-context.mjs`
  (`npm run audio:review:context:two-schedules-2d`).
- Офлайн-тесты: `scripts/audio-review.test.mjs` (`npm run test:audio-review`,
  также входят в `npm run test:audio`). Сеть и API в тестах не используются.

## Главное правило: модель слушает вслепую

Аудиомодель получает **только WAV и нейтральное задание**: распознать речь по
звуку и оценить слышимое. Сценарий, ожидаемые реплики, их порядок, роли и
таймкоды в запрос **не попадают никогда — в том числе при `--context`**.
Перед отправкой движок дополнительно проверяет тело запроса
(`assertNoContextLeak`); запрос с `--context` и без него байт в байт одинаков
(это проверяет тест).

Причина: в двух пробах одного и того же WAV ответ со сценарием в задании
повторил сценарий дословно и с его таймкодами, а ответ без сценария разошёлся
с ним по словам и времени. Двух запросов недостаточно, чтобы приписать все
различия сценарию — часть может быть вариативностью модели, — но подсказка
сценария делает сравнение несамостоятельным, поэтому она убрана.

`--context` используется **только локально, после ответа модели**: код
сопоставляет независимую расшифровку с ожидаемыми репликами. Второго
платного прогона со сценарием нет.

## Запуск

```bash
# Контекст ролика №12 (текст реплик, плановое время и проверенное размещение
# файлов голоса в композиции) — только для локального сравнения
npm run audio:review:context:two-schedules-2d

# Бесплатно: проверка файла, дорожки, нарезки и измерения FFmpeg
npm run audio:review -- --input out/balago-two-schedules-2d.mp4 \
  --out out/audio-review/two-schedules-2d-probe12 --start 0 --duration 12 --dry-run

# Короткая платная проба (12 с, один запрос)
npm run audio:review -- --input out/balago-two-schedules-2d.mp4 \
  --out out/audio-review/two-schedules-2d-probe12 \
  --context out/audio-review/two-schedules-2d.context.json --start 0 --duration 12

# Полный анализ ролика (120 с → 7 фрагментов, 7 запросов)
npm run audio:review -- --input out/balago-two-schedules-2d.mp4 \
  --out out/audio-review/two-schedules-2d \
  --context out/audio-review/two-schedules-2d.context.json
```

| Аргумент | Назначение |
| --- | --- |
| `--input <файл>` | MP4, WAV или MP3 (обязательно) |
| `--out <каталог>` | каталог отчётов (по умолчанию `out/audio-review/<имя файла>`) |
| `--context <json>` | необязательный сценарий — только для локального сравнения |
| `--start <с>` | начало диапазона, по умолчанию 0 |
| `--duration <с>` | длина диапазона, по умолчанию до конца файла (обрезается по концу) |
| `--dry-run` | всё, кроме обращения к API |
| `--auth claude_proxy\|key` | способ авторизации (по умолчанию `AUDIO_QA_AUTH_MODE`, иначе `key`) |
| `--chunk`, `--overlap` | длина фрагмента и перекрытие (20 и 2 с) |
| `--max-tokens`, `--timeout` | лимит ответа (2500) и ожидание одного ответа (180 с) |
| `--max-attempts` | попытки при временных ошибках (3, не больше 5) |
| `--cache-dir`, `--no-cache` | каталог кэша / отключить кэш |

Коды выхода: `0` — complete или dry_run, `2` — partial, `1` — failed,
`64` — ошибка аргументов.

### Формат `--context`

```json
{
  "lines": [
    {
      "id": "f01", "role": "father", "text": "Бүгүн балдарды качан алып келесиң?",
      "plan_at": 3.1,
      "placement": { "file": "public/audio/…/f01.mp3", "file_sha256": "…",
                     "file_from": 3.1, "file_to": 5.007,
                     "speech_from": 3.1, "speech_to": 4.807 }
    }
  ]
}
```

- `plan_at` (или `at`/`start`) — плановое время сценария. Используется только
  для выбора реплик, ожидаемых во фрагменте. **Привязкой ко времени не
  считается.**
- `placement` — проверенное размещение реально подключённого файла голоса.
  Для ролика №12 его строит `audio-review-two-schedules-context.mjs`: тот же
  расчёт, что в композиции (`buildTs2Cues` по манифесту + округление до кадра,
  как в `Ts2Audio`), плюс проверка самого файла (существует, SHA-256,
  длительность по ffprobe совпадает с манифестом). `file_from/file_to` — где
  звучит файл; `speech_*` — окно речи внутри файла по таймингам манифеста.
  Совпадение отрендеренного MP4 с этим манифестом автоматически не
  проверяется: MP4 нужно рендерить из того же состояния репозитория.
- Также понимается `{"expected_text": "…"}` (без времени — сравнивается,
  только если один фрагмент покрывает весь файл).

## Как устроен анализ

1. **FFprobe** проверяет файл и аудиодорожку.
2. **FFmpeg** вырезает диапазон и фрагменты в PCM16 WAV с исходной частотой и
   числом каналов — без нормализации и пересэмплирования.
3. **Измерения** (`measurements`, отдельно от мнения модели):
   `ebur128=peak=true` (Integrated LUFS, LRA, true peak), `astats`
   (sample peak, RMS, flat factor, шум) для диапазона и каждого фрагмента;
   профиль RMS окнами 0,25 с и **ориентиры для ручной проверки** — тихие
   участки и резкие подъёмы громкости. Ориентиры не определяют текст,
   говорящего и даже наличие речи (в миксе музыка и эффекты) и к репликам
   автоматически не привязываются.
4. **Нарезка**: равные фрагменты ≤ 20 с с перекрытием 2 с, без пропусков.
5. **Запрос** на фрагмент: `POST https://api.openai.com/v1/chat/completions`,
   `model: gpt-audio-1.5`, `modalities: ["text"]`, `store: false`,
   `max_completion_tokens`, задание `audio-review-v2-blind` + `input_audio`
   (`format: "wav"`, base64). В задании — только длительность фрагмента и
   какие его края искусственные.
6. **Ответ**: Structured Outputs у модели не заявлены — JSON просится текстом
   и проверяется своим парсером. Исходный текст сохраняется всегда.
   Оценки 1–5 могут быть `null` с пояснением в `score_notes` (например, если
   эффектов не слышно) — высокая оценка по умолчанию не ставится.
7. **Локальное сравнение** со сценарием (`script_comparison`) — см. ниже.
8. **Время** — см. ниже.

## Сравнение со сценарием (код, не модель)

- Реплики фрагмента выбираются по `placement`, иначе по `plan_at`.
- Слова выравниваются по порядку (Нидлман — Вунш по словам) через все
  фрагменты речи модели сразу, поэтому реплика, разделённая моделью на части,
  и несколько реплик, слитых в одну часть, сопоставляются корректно.
- Нормализация — только регистр, пробелы и пунктуация. Слово, разнесённое
  пробелом («эки де»), склеивается, если слитное написание есть на другой
  стороне (`spacing_normalized`). **У/ү, о/ө, н/ң, ы/и не приравниваются**,
  окончания и отрицания не стираются.
- Каждое расхождение показано явно: `«иштеп алам» → «иште болом»` с видом
  (`kyrgyz_letters`, `word_ending`, `different_words`,
  `possible_negation_difference`, `missing_in_recognition`, …).
- Статусы: `match`, `partial`, `mismatch`, `unclear`; в своде ещё
  `outside_range` и `not_checked`. `unclear` ставится, если реплика на краю
  фрагмента, модель пометила речь неразборчивой или не уверена, сопоставление
  неоднозначно или модель не разобрала слов. **Реплика не объявляется
  пропущенной только потому, что модель её не разобрала.**
- Расхождение означает «сценарий ≠ распознавание модели», а не доказанную
  ошибку озвучки. Исходная расшифровка модели хранится рядом без исправлений.

## Время

У каждого замечания (`model_assessment.issues[].time`):

| Поле | Что это |
| --- | --- |
| `fragment` | границы WAV, который реально вырезал FFmpeg и отправил — **подтверждено** |
| `model_estimate` | время модели внутри фрагмента и в шкале файла — **не проверено**; отрицательное, перевёрнутое или выходящее за фрагмент помечается `valid: false` без обрезания |
| `verified_narrower` | более узкая проверенная привязка или `null` с объяснением |
| `display_basis` | `fragment` (по умолчанию) или `project_audio_placement` |

Более узкая привязка возможна только для роликов проекта: замечание модели
ссылается на свой фрагмент речи (`heard_segment`), код сопоставил его с
репликой, у реплики есть проверенное `placement` — тогда показывается
интервал звучания файла ∩ фрагмент. Это место файла реплики, а не точное
место дефекта внутри неё. Плановое время сценария привязкой не считается.
Для произвольного MP4 остаётся честная привязка к фрагменту.

Замечания **не удаляются** у краёв и **не склеиваются** по времени модели и
категории. Возможный артефакт нарезки (`possible_boundary_artifact`) и
возможный дубль из перекрытия (`possible_duplicates`) — только пометки
«не подтверждено».

## Отчёты

В каталоге `--out`:

- `audio-review.json` — `status` (+ `status_meaning`), `audio_input_sent`,
  `api_success`, `context_sent_to_model: false`, SHA-256 файла, диапазон,
  `coverage`, модель, `prompt_version`, `report_format_version`,
  `measurements`, `chunks` (статусы, попытки, `finish_reason`,
  `incomplete_reason`, usage, исходный текст), `model_assessment` (исходная
  расшифровка с `model_time`, оценки и пояснения, замечания), локальное
  `script_comparison`, `unchecked_ranges`, `manual_check`, `limitations`,
  `usage_this_run`;
- `audio-review.md` — то же для чтения, с разделами «Охват», «Места для
  ручной проверки», «Ограничения»;
- `raw/chunk-NN.request.json` — тело запроса без base64;
- `raw/chunk-NN.response.json`, `raw/chunk-NN.model-text.txt` — исходный ответ;
- `range.wav`, `chunks/chunk-NN.wav` — именно те байты, что измерялись и отправлялись.

**Статусы.** `complete` — все выбранные фрагменты обработаны (полный,
разобранный ответ). Это статус обработки, **не оценка качества ролика**.
`partial`, `failed`, `dry_run` — как раньше. Статусы фрагментов: `analyzed`,
`truncated` (`finish_reason: length`), `incomplete_response` (иной
`finish_reason`), `api_error`, `empty_response`, `parse_error`, `skipped`,
`dry_run`/`dry_run_cached`. Усечённый ответ не считается проверкой, не
кэшируется; частично разобранное лежит в `partial_result` только для чтения.

`audio_input_sent` — curl/fetch действительно передал всё тело с аудио в этом
запуске; `api_success` — HTTP 200 с непустым текстом в этом запуске. При
ответе из кэша оба `false`, а `chunks[].from_cache` — `true`.

## Кэш, повторы и отказы

- Кэш — `<родитель --out>/.audio-review-cache/`. Ключ: SHA-256 фрагмента WAV,
  модель, версия и текст задания, параметры запроса (`modalities`, `store`,
  `max_completion_tokens`). **Сценарий в ключ не входит**: смена только
  `--context` пересчитывает локальное сравнение из кэша без нового платного
  прослушивания.
- Кэшируются только полные (`finish_reason: stop`) и разобранные ответы.
  Записи старого формата (v1, ответы, полученные со сценарием в задании) не
  используются.
- Повторы только для временных ошибок (429 rate limit, 5xx, таймаут, сеть):
  до `--max-attempts` попыток с паузой 2 → 4 с.
- Без повторов и с остановкой оставшихся фрагментов: `insufficient_quota`
  (`credit_balance_exhausted`), 401, 403, `model_not_found`.

## Доступ к OpenAI

| Режим | Где | Как |
| --- | --- | --- |
| `claude_proxy` | облачная среда Claude Code | `AUDIO_QA_AUTH_MODE=claude_proxy`. `curl`, JSON через stdin, **без** своего `Authorization`: заголовок подставляет прокси. `OPENAI_API_KEY` не нужен. |
| `key` | локально, будущий сервер | `OPENAI_API_KEY` в окружении; запрос через `fetch`. |

Ключи, заголовки авторизации и окружение не печатаются и не сохраняются;
текст ошибок API проходит через `redact()`. Проверка TLS не отключается.

## Ограничения

- Оценки 1–5, `certainty` и `confidence` — мнение модели, не измерение и не
  гарантия.
- Распознавание кыргызской речи моделью может быть ошибочным; один и тот же
  WAV в разных запусках даёт разные расшифровки. Одна успешная проба не
  доказывает достоверность распознавания.
- Подтверждено только время фрагмента FFmpeg; время модели не проверено.
- Ориентиры громкости не определяют текст, говорящего и наличие речи.
- Инструмент получает только звук: о синхронизации губ и изображении выводов нет.
