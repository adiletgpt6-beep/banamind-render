# Цикл одного выпуска
## Роли
ChatGPT — координатор: читает GitHub, принимает три источника, пишет новый сюжет и полное TASK, добавляет 100 улучшений, готовит краткий запуск.
Claude Code — производитель: читает GitHub, делает сценарий окончательной речи, графику, звук, рендер, обложки и выдачу; ведёт STATUS.
Один исполнитель обновляет общий REGISTRY; параллельные исполнители меняют только свой выпуск. Пользователю не требуется переносить большой контекст вручную.

## Этапы
1. AWAITING_SOURCES: подготовлен TB-ID; книги не выдуманы.
2. SOURCE_READY: все 3 книги реально доступны и записаны во внутреннем SOURCE_MAP.
3. BRIEF_READY: общий вопрос, сюжет, выбранный герой, план сцен, NOVELTY.
4. READY: полный TASK и 100 новых улучшений уточнены, проверены и зафиксированы; редакционные решения делегированы владельцем.
5. IN_PRODUCTION: окончательная речь → озвучка → пилот → анимация → полный рендер → обложки/метаданные.
6. QA_REVIEW: измерения, выборочный/полный просмотр с честным объёмом проверки, исправления.
7. DELIVERED: файлы существуют, ссылки и пять обложек проверены; результат передан владельцу.
8. USER_APPROVED: владелец принял результат. Публикация на YouTube этим не подтверждается.
BLOCKED и CANCELLED требуют причины и ближайшего шага. IMPORTED_REFERENCE применяется к первому фильму с одобренной историей при неполном переносе исходников.

## Git-процесс
- Системная ветка: docs/three-books-production-system, PR на main. Наличие merge проверять.
- Новый выпуск: feature/three-books-tb-NNN-<slug> от актуального состояния системы.
- Если система ещё не в main, эпизодный PR направлять на системную ветку, явно записать базу; после её merge проверить перенаправление на main.
- Проверять существующую ветку/PR до создания дубля. Не делать force-push и не сливать чужие PR.
- Общий реестр обновлять при подготовке задания и после значимого результата, не ждать неопределённо долго merge.
- HANDOFF и STATUS содержат реальную ветку/PR/commit; ссылки «main» допустимы только когда там уже есть файлы.
- Коммит со статусом содержит новые реальные результаты, а не фиктивные ссылки. Исторические статусы не стирать.
- Рендерить только нужный фильм. Документационные коммиты серии исключены из общего рекламного render.yml.

## Восстановление
Сначала установить ветку/HEAD и найти TASK/STATUS, затем сверить существующие артефакты и выбрать первый незавершённый шаг. Чтение короткого сообщения из PROMPTS запускает этот процесс. Готовые звук и сегменты не перегенерировать без причины.

## Границы текущей подготовки
Создана постоянная документационная система и лёгкая проверка структуры. TTS, рендер и выдача новых TB-выпусков ещё должны быть реализованы/найдены Claude по реальному проекту. Наличие workflow проверки документов не означает наличие автоматического видеопроизводства.
