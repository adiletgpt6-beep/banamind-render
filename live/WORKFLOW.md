# BalaGo LIVE — производство 150 живых роликов

## Нумерация и источник правды
Каждый ролик: LIVE-001 ... LIVE-150. В GitHub хранить текстовые карточки задач и реестр результатов, а не исходные MP4. Один ролик — одна рабочая ветка/PR, отдельная карточка статуса. Постоянные правила: ../AGENTS.md, ../CLAUDE.md, STYLE.md. Для LIVE применить специальное исключение: не добавлять повторно рекламный CTA, уже произнесённый автором. Краткая новая сессия Claude Code на каждое видео: прочитать правила, задачу, карточки последних 5–10 роликов.

## Этап A: существующий способ загрузки
Исходники уже могут храниться в GitHub Releases. Для нового задания достаточно ссылки на конкретный Release и имени исходного файла. Уже имеющийся референс закреплён в STYLE.md и при необходимости — отдельной ссылкой в общей документации. **Не требовать повторной загрузки референса** для каждого видео.

## Этап B: мобильная загрузка без GitHub
Сделать закрытую мобильную страницу с одной кнопкой «Загрузить». Сервер выдаёт временный URL для прямой загрузки MP4 в приватное объектное хранилище (например, Cloudflare R2) и создаёт текстовое задание с LIVE-ID, ключом файла, длительностью/размером и статусом. Секреты остаются на сервере, не в браузере и не в GitHub-файлах. Только уполномоченный рендер-процесс получает временный доступ к исходнику. Загрузка в чат ChatGPT сама по себе не делает видео доступным Claude Code.

## Этап C: автоматический запуск
Отдельный workflow для live-видео читает карточку и запускает Claude Code/инструменты монтажа с нужными правами. Сначала собирается недорогой preview. После согласия владельца — рендер оригинала и загрузка в Release/защищённое хранилище. Не запускать существующий общий рендер 2D-видео из-за правки карточки живого ролика. Не создавать платную массовую сборку.

## Карточка задания
ID, тема, исходник (ссылка/ключ), длительность/формат, короткая расшифровка при наличии, ключевой смысл, аудитория, выбранная концепция (определить после анализа), избегать повторов предыдущих работ, список смысловых вставок, статус: recorded → queued → preview → changes → approved → delivered. Реальные замечания владельца записывать в карточку и учитывать в следующих заданиях.

## С чего стартовать
1. Утвердить гибкий STYLE.md.
2. Переделать LIVE-004 под более спокойный монтаж на основе уже загруженных исходников и имеющейся предыдущей версии; не перезаписывать оригинал.
3. После одобрения стиля начать пилот мобильного загрузчика.
4. Затем автоматизировать запуск задач и масштабировать серию до 150.
