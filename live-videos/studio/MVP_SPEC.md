# BalaGo Video Studio — пилот автоматической загрузки с телефона

## Цель
Владелец BalaGo снимает 150 живых видео. Он хочет **передать одно MP4 с телефона** через закрытую мобильную страницу и получить оформленную задачу `LIVE-NNN` в GitHub без GitHub Release, ручного копирования ссылок или повторной загрузки референса. Впоследствии — автоматический запуск монтажа через Claude Code, но **первый этап не включает неконтролируемые платные автоматические рендеры**.

**Статус этого документа: ТЗ на реализацию, не готовый работающий сайт.**

## Архитектура пилота

- Отдельное изолированное приложение `apps/balago-studio/` (например Next.js на Vercel). Не встраивать без проверки в существующий публичный сайт BalaGo и не вмешиваться в Remotion/2D-проект.
- Приватный доступ: единственный авторизованный владелец. Не полагаться на «скрытый» URL как на авторизацию. Защищать API-маршруты; rate limits, короткая сессия, CSRF/Origin проверки, защита от перебора.
- Видео хранятся **не в Git-репозитории** и не проходят через Vercel Function как 60+ МБ тело запроса. Браузер напрямую загружает файл по короткоживущему signed PUT URL в **приватный Cloudflare R2** (или совместимое private S3 хранилище). Безопасно показать прогресс, ошибки, повторить upload. Подготовить инструкции для CORS настроек бакета под домен приложения.
- Секреты `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, секрет авторизации и GitHub App/private fine-grained token **только в секретах хостинга**. Никогда не коммитить, не печатать в логах, не выдавать браузеру. Signed URLs не хранить в GitHub задачах: только объектный ключ и безопасные метаданные.
- Принять MP4/MOV по белому списку расширений/MIME, проверить заголовок и реально сохранённый объект после upload (HEAD: существование, размер, Content-Type, тип данных), ограничить максимальный размер на уровне API; защищать ключи от path traversal; запретить публичный list/download бакета.
- Уникальные объектные ключи без персональных данных, например `live/raw/<uuid>/source.mp4`. Валидация имени, размера, длительности (на клиенте опционально); не считать метаданные от браузера доверенными.
- После успешной загрузки и проверки файла нажатием «Создать задание» создать GitHub Issue или новый `live-videos/tasks/LIVE-NNN/TASK.md` и `task.json` через серверную GitHub-интеграцию, сохранив только `sourceObjectKey` и описание. Надёжная идемпотентность и защита от двойного нажатия/гонки номеров. Проверить ещё существующие LIVE-001...LIVE-004 (не перенумеровывать).
- **Не менять существующую схему `task.json` необдуманно**: `live-videos.yml` сейчас запускает рендер при каждом изменении `task.json`. Новая задача с отсутствующей композицией НЕ должна запускать Actions, иначе CI упадёт/потратит минуты. Первый этап: создавать **GitHub Issue** с источником и статусом `recorded` + приватный `uploadId`; конвертацию в исполняемый `task.json` делать только после готовности композиции. При необходимости отдельный валидируемый `intake.json` и реестр, который сам по себе не рендерит.
- Референс монтажа уже есть: `live-videos/reference/REFERENCE.md`. Не просить его повторно. Каждый ролик отличается по стилю, но соблюдает правила `AGENTS.md`, `CLAUDE.md`, `live/STYLE.md`, `live-videos/RULES.md`. Для живого CTA показываем синхронную графику, но не повторяем голосом. Субтитры кинетические, без постоянной синей плашки.
- Самостоятельная авторизация доступа монтажного процесса к R2 через секреты Actions/Claude Code, **не публиковать временные download URL в GitHub Issue**. Если секреты не подключены, Issue должен содержать ключ объекта и инструкцию настройщику, а не ложную ссылку.
- Будущий этап — постановка через Issue/dispatch в Claude Code; **первый пилот не должен автоматически запускать десятки дорогостоящих рендеров**. Один входящий ролик — одна карточка и вручную подтверждаемое превью.

## Интерфейс для телефона

Название **BalaGo Video Studio**, мобильный экран с логотипом и тремя действиями:
1. **Загрузить видео** — выбор MP4/MOV, просмотр имени/размера, прогресс/ошибка, защита от двойной загрузки.
2. **Кратко о видео** — необязательное название или тема и необязательная текстовая заметка по монтажу (без необходимости писать полный промпт).
3. **Отправить в работу** — подтверждение файла и создание задания, затем карточка `LIVE-NNN` со статусом «Получено» и ссылкой на GitHub Issue, которую можно открыть на телефоне.

Должно нормально работать на Android Chrome в вертикальном режиме и поддерживать кыргызские/русские буквы, без хардкода WhatsApp в форме загрузки.

## Продуктовые границы

Первый результат — **мобильная страница + безопасный приём исходника + автоматическая GitHub-карточка**. Автоматический монтаж, выбор AI-стиля, смонтированное превью и его утверждение — отдельный этап после проверки upload-пайплайна и подключения нужной интеграции для Claude Code. Не выдавать проект-документ за работающую систему.

## Условия готовности пилота

- MP4 около 60 МБ загружается **напрямую в приватный R2** с телефона и отображает прогресс.
- После загрузки появляется одна карточка `LIVE-NNN`, даже при повторном нажатии.
- Нет открытых источников/секретов/ссылок на raw MP4.
- Нет автоматического старого рендера 2D и массовых счётов GitHub Actions.
- Пользователь получает рабочий адрес Studio и инструкцию входа после подключения хостинга/учётных записей; пока подключения нет — честный список недостающих переменных и действий.
